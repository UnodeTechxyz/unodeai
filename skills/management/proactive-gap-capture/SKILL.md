# Proactive gap capture

Capture important gaps without hijacking the current task.

Procedure:

1. Decide whether the gap blocks the current request. If it blocks, surface it immediately. If not, keep going.
2. Record the gap in one compact note: symptom, impact, suggested owner, and when to revisit.
3. Avoid expanding scope by default. A discovered improvement is not permission to implement it.
4. Mention the gap in the final handoff only if it affects release confidence or would save the user real time.
5. For recurring gaps, suggest a task card or backlog item rather than repeating the same warning.

Good gap capture feels like memory, not bureaucracy.
