# Optional helper runtime and effects

These are source resources, not auto-loaded plugins. Loading or reading this skill executes no helper, import, installation or hook. No dependency availability or successful native Office run is implied.

- Python helpers use Python 3 and, depending on the helper, defusedxml, lxml, python-pptx or Pillow. Node apply_theme uses jszip resolved through pptxgenjs. LibreOffice rendering also needs soffice; thumbnail rendering invokes pdftoppm. Inspect imports and the actual CLI in the selected source before running. Packages are not bundled here.
- office/helpers/__init__.py supplies safe_extract and rezip for selected package files and unpacked directories. Validators read package XML and may create temporary unpacked copies; repair options can mutate supplied files. Use task-owned staging for mutations.
- office/soffice.py can create OS-temp lo_profile_ and lo_input_ directories and copy drawing inputs. Its optional Linux socket shim writes fixed OS-temp lo_socket_shim.c, invokes gcc to produce a shared library, removes the C file and retains the library. This is runtime compilation, not a bundled binary. Cutting selected external links is not a no-network guarantee.
- docx accept_changes writes a fixed /tmp/libreoffice_docx_profile macro profile, copies the selected document, and calls soffice. Timeout can produce success text without verifying tracked changes. comment and merge_runs edit selected document contents; validators/redlining inspect revision structures. These checks are not full Word/native rendering verification.
- pptx slide_text reads deck content; thumbnail writes JPG grids under its output prefix (default thumbnails, which can overwrite prior grids), uses OS-temp files and native rendering. add_slide edits package bookkeeping; clean deletes unused parts in the supplied unpacked folder. apply_theme writes the deck in place by default.
- Source helpers retain their original relative imports and defaults. The two families share office support code; consult upstream-files.json for exact per-file identities. Source code can have effects beyond argument names: command argument inspection is not an OS read/write sandbox.

UnodeAi routes Python bytecode to its owned cache when no explicit user override applies. That does not redirect helper output, LibreOffice profiles or all temporary files. Codex temporary-directory exclusions and existing sandbox permissions remain unchanged; a helper needing an unavailable path/runtime may fail. No automatic temp grant, source-copy fallback or new confirmation is introduced. Generic host/helper qualification does not establish that every upstream helper works on every backend. Verify the selected operation's artifact and report unavailable checks honestly.

Static source inventory: scripts/__init__.py and office/validators/__init__.py are package initializers. office/helpers/pptx_chart.py, pptx_slide.py and pptx_theme.py inspect XML/package structure; helpers/__init__.py owns package extraction/rezip and temporary output replacement. validators/base.py supplies lxml schema checks and repair writes; validators/docx.py adds Word checks/repair writes; validators/pptx.py adds presentation checks and temporary comparison unpacking; validators/redlining.py compares revisions using temporary originals. validate.py exposes --auto-repair (modifies selected input in place), --original and --author. docx comment.py creates comment parts and relationships, defaults the author to Claude, and can use --output; merge_runs.py normalizes selected XML runs. pptx slide_text.py requires python-pptx; add_slide.py duplicates a slide/layout, updating relationships/content types; apply_theme.js rewrites selected theme/deck XML. All initialization/imports occur only when intentionally executed by an ordinary command. Static review identifies effects, not runtime correctness or complete containment.
