# Requesting code review

Make review easy to attack.

Review packet:

1. Summary of what changed and why.
2. Files changed, grouped by concern.
3. Behavior to verify and known non-goals.
4. Tests/checks run with exact commands and outcomes.
5. Risk areas where the reviewer should be skeptical.
6. Any shortcuts, unverified assumptions, or follow-up work.

Do not ask for a rubber stamp. Ask for the reviewer to try to break the change.
