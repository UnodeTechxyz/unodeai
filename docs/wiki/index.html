UnodeAi 0.9.76

Delegate to an AI team. Keep the receipts.

Every AI coding tool can tell you it finished. UnodeAi can show you what it did. A project manager agent breaks your goal into tasks and delegates to specialists — each on the model you choose — and what an agent claims is kept separate from what the framework observed. No agent’s “done” is printed as evidence, and no model grades another model’s work. Export any run as one Markdown file a client or auditor can read without installing anything, or as portable JSON that carries no request text, instructions, command lines or file contents, and declares what it does keep. A coordinator that cannot finish reports partial or blocked with reasons rather than going quiet. Runs in VS Code, Cursor and compatible editors — Solo for quick tasks, a PM-led crew for larger work, workflows for repeatable processes.

Quick Start

  1. Install UnodeAi from Open VSX (search UnodeAi in Extensions), or from a .vsix file. Cursor's marketplace mirrors Open VSX and can lag, by an amount that varies: at the 0.9.33 release the new version was not yet offered 40 minutes after publication and was being served 6 hours after it, while 0.9.34 was installable 27 minutes after publication, 0.9.36 within 42 minutes, and 0.9.41 within the hour it shipped. Expect minutes to a few hours, and read a version missing right after a release as the mirror catching up, not a broken install. To get it immediately, in Cursor use Ctrl+Shift+P → Extensions: Install from VSIX.... UnodeAi is not on the Microsoft VS Code Marketplace. After replacing an installed version, fully quit and reopen the editor — a reload is not always enough.
  2. Run UnodeAi: Run Setup Wizard.
  3. In the wizard, choose an OpenAI-compatible connection or Claude Headless. Codex Headless remains visible as Coming soon, but cannot be selected or set up in this release.
  4. Create a team in the wizard, then select Finish and continue.
  5. Finish opens the Workbench when a team exists; otherwise it opens the Team panel's create-team path.
  6. Send a goal to the Project Manager in the Workbench.

The available setup doors show their runtime, billing path, and egress summary before saving. OpenAI-compatible connections include Unode, Roam, OpenRouter, OpenAI API, and any named custom gateways. Select ＋ Add custom gateway… in that menu to create one without leaving the wizard: the host collects its display name, HTTPS endpoint, and masked key in native prompts, then selects the new gateway. The key never enters the wizard webview. Claude setup pre-fills claude login in a terminal but never executes it. Codex Headless is Coming soon and has no setup action.

Teams and Roles

The default software crew is Project Manager, System Architect, Senior Developer, and Reviewer. The picker's Software group also offers the Software Engineering Team — that crew plus QA Engineer and Technical Writer as first-class seats, seven agents including the standalone Solo every team ships with. You can also add QA, DevOps, Technical Writer, Security, Data Engineer, Product Manager, Solo, and knowledge-work specialists individually. The catalog contains 52 role templates and 25 team presets, including Contract & Compliance (contract analyst, privacy officer, GRC and procurement analysts — every output stopping where a person with authority must decide, and sanctions or export-control questions refused and routed rather than answered) and Website Design & Development (product designer, frontend engineer, content strategist, SEO specialist and QA).

Beyond the software crew, the team picker offers ready-made knowledge-work presets — Business Planning, Business Analysis, Financial Analysis, Marketing (content, growth, research, SEO/analytics), and Sales (SDR, account executive, sales engineer, customer success). These use the same PM orchestration with non-code specialists and analysis-oriented team rules.

Saving a team for one project or for all of them

UnodeAi: Save Team… asks which scope. This project writes .unode/teams/<name>.json, which travels through git to whoever clones the repo. All projects keeps it in UnodeAi's own per-user storage so it is there in the next workspace you open. The picker lists both and labels each row, so two teams may share a name. Automatic snapshots taken before a roster is replaced are always per-project.

A team that crosses that boundary never brings permissions with it, and says what it dropped. A folder permission is kept only if, after the path is resolved and symlinks followed, it lands inside the workspace you are opening it in — otherwise a grant naming a folder in the project you configured it in would silently hand these agents access to that one. Per-agent MCP grants are removed and re-granted here, because a grant made about one project's server must not attach itself to a different server that shares its name. And an All-projects team never stores an agent's env: a file spanning every project on the machine cannot tell a proxy host from a key.

Build your own agent

Every section carries its own Advanced fold, and folds start closed. No fold opens itself: a closed section stays closed until you click it. Skills and Tools show what is selected and fold the rest into a full list, and model fine-tuning comes before them. Double-clicking a team member opens that agent’s Workbench conversation.

Run UnodeAi: Build an Agent to open the Agent Builder — a form to create or edit a custom agent (name, a built-in or custom role like CEO, icon, model, system prompt, capability tools, folder access, and MCP grants) without touching JSON. A new agent opens blank, with Select a role… in the Role dropdown: picking a role is what populates the name, instructions, icon, model, and default skills, all of which you can then change. The chosen connection is authoritative: unavailable tool skills and MCP grants are disabled with an explanation, and the host rejects forged or hand-edited requests. If a role switch replaces instructions you wrote yourself, one click restores them; save without restoring and the replaced text is still kept as the agent's undo record. Attach any number of skill playbooks from the skill library: market-proven procedures (OWASP review, dependency-risk triage, test-coverage gaps, accessibility audits…). The instructions receive only each playbook's name and when-to-use line; the full procedure is loaded on demand when it is actually relevant, so the agent arrives knowing how to do the job without carrying every procedure in its prompt. The in-app library stays lean; the builder links out to the full skill library for the long tail. Save, and the agent joins your team like any preset.

Tool calling method. Auto starts with native tool calling. The builder warns for model families that have leaked tool calls as text: the first tool use may visibly retry as UnodeAi switches to XML for that session, and tool following may be weaker. This is a warning, not a block: Native and XML remain explicit choices and any model id may still be typed by hand.

Workbench, Transcript, Plan, and Act

Codex Headless is Coming soon: its connection card is intentionally disabled. It cannot be selected, set up, made the default, or started in this release. A persisted or hand-edited Codex route is rejected by the extension host before a backend is constructed.

Claude Headless agents stream partial text and thinking during a turn, and their native tool results complete the same tool cards as OpenAI-compatible agents. Every Claude native tool call is mediated before it runs by a fail-closed hook, including calls made inside Claude's own subagents.

Workbench is the editor-first conversation surface. UnodeAi: Open Workbench starts work in or reveals one native editor tab with one agent selector, a compact task/lifecycle/route/model/context/cost header, a full-width transcript, and a composer pinned at the bottom. It can be moved with normal editor-tab drag targets and closed with the native tab close. Reopening restores the same host-owned session and never starts or duplicates a backend turn. The changed-files command opens an Edit history rail: restored entries remain as history rather than falsely reading as still changed.

Select code or text in an in-scope editor or UnodeAi diff, then choose Add to UnodeAi from the editor lightbulb to place that selection in the selected agent's composer before sending. It is absent when there is no selected team agent, and it cannot turn an outside file into context unless that agent's existing Folder Access read scope already permits it.

If a turn cannot run yet, the shared Workbench transcript renderer says why and offers one next action: Create a team when there are no agents, or Open Settings when no available connection exists or its API credential is missing. The host checks readiness without sending endpoint, secret-name, or credential details to the webview.

The compact Team sidebar is navigation and status: session rows lead showing each agent's current responsibility. A row stays one line until you ask for more — hovering swaps the status word for that agent's controls (Stop/Start, Restart, ⚙️ Configure, Terminal, Remove), and the ▾ chevron expands it in place for model, provider, role, live context/cost/turns, skills, and changed files. The row's controls are always visible — ⚙️ Configure opens the agent's Agent Builder page — and it carries no status word: the first glyph says it, and the dot on the agent's icon separates working, idle, stopped, and error. The title bar shows the version beside the title and pins Open Workbench, Add Agent, ⋯ Team Actions, Settings, Message, Solo, and Collapse/Expand; ⋯ Team Actions names everything not pinned (Build an Agent, Create or Switch Team, Save/Open Saved Team, Marketplace, Start/Stop All, Team Rules, Restore File Checkpoint, concurrency mode, Security, Evidence Report). Narrowing the sidebar wraps the collapsed agent chips instead of scrolling them out of sight. The Chat sidebar view (unode.chat) is the compact alternate entrance to the same responsive transcript renderer, not a second main surface; both containers can be open and only visible containers receive live updates. unode.workbench.autoOpen defaults to true for chat and session actions, but never opens a Workbench merely at activation. Turn it off if you prefer the sidebar. Use UnodeAi: Toggle Workbench Composer Focus (Ctrl+Alt+Enter, or Cmd+Option+Enter on macOS) to move between the Workbench surface and composer.

Changed files. The Workbench title bar's Show Changed Files icon opens a rail listing what the selected agent changed, newest first; each entry opens that edit in the native VS Code diff editor (side-by-side or inline, F7 navigation, folded context, and the live file on the right so a correction can be typed into the diff), and ⟲ restores that one file after confirming. The rail starts closed and remembers its state per workspace; on a narrow editor it becomes an overlay drawer rather than hiding, so the title action never says Hide Changed Files while nothing is on screen. Worktree lane diffs use the same editor; a lane-level view asks which changed file to open, and the base side is pinned to the commit the tab was opened against (named in the title) so an open diff never re-points when the base branch moves. The diff inside an inline tool card is unchanged — an approval keeps its diff attached to the decision.

Approvals stay inline with the command, URL, or diff they decide; they are not moved into a detached queue. While a decision is pending, its card reserves the floating composer's measured height only while it is visible, so you can scroll the decision completely above the dock without leaving a permanent transcript gap. The status bar shows 🔐 N waiting, the UnodeAi activity container carries the same count, and the affected Team row is locked. Click the status-bar item or row to open the relevant Workbench transcript and scroll to its existing card. Agent requests never steal focus or autofocus an allow button. consent_required is a waiting state, not an error; expiry stays visible as Denied — timed out. Public-web approvals allow a 15-minute human window, independent of the fail-closed local transport clock.

Every agent has a persistent chat. The Workbench transcript supports live streaming, Stop, Steer, tool cards, diffs, command output, analysis cards, context usage, todos, approvals, and import/export. Clear deletes a transcript; Archive hides it without deleting (restore later via View Archived Chats). Agents can also search_files (regex → file:line) and delete_file (sandboxed + checkpointed) so they don't resort to scratch scripts or blocked shell tricks.

The context meter says where its denominator came from, and the button beside it acts on that. The meter reads like 41% of an assumed 1,048,576 tokens, with a separate ⤄ icon button next to it that compacts on click. The reading is labelled configured (you typed it), measured (the gateway advertised it through the consented model-list read), provider-refused (a request that size was rejected), or assumed (the documented fallback). Clicking it compacts older turns into a rolling summary immediately — whether or not the automatic threshold has tripped — and reports how many messages it dropped, or says plainly that it dropped none.

A coordinator can end work it cannot finish. close_assignment takes complete, partial, or blocked; the latter two require one entry per undelivered item with a concrete reason, and complete is refused while any settled delegation still has no recorded decision. partial and blocked are reportable outcomes, not failures to hide — before this existed the vocabulary covered only a delegate’s returned result, so a coordinator handed an impossible job had no terminal state and simply stopped. If an assignment ends with no conclusion, UnodeAi appends one itself, labelled as UnodeAi’s rather than the coordinator’s, carrying only mechanical facts and never a claim about whether the work was correct.

Portable Run Evidence answers who, where, and whether the changes match without carrying the private originals. The current portable-run-evidence/3 schema distinguishes complete and partial closeout, carries delegation completion separately from its evidence verdict, and exports readReceipt: observed | not-observed. A human decision’s exact actor remains in the internal ledger and becomes approver-1 in portable JSON; an exercised MCP grant has no approver because nobody decided at that moment. Exact custom route ids, private gateway hostnames, and endpoint-bearing privacy ids stay internal while the portable form carries builder-validated connection, execution, and privacy categories. Complete changes carry SHA-256 hashes computed while write bytes exist, never a diff or source. Relative changed paths, timestamps, and hashes are deliberately retained and declared; historical or incomplete observations remain explicitly unavailable.

When the meter has no number, it says why. The pill reads 41% of an assumed 1,048,576 tokens · Compact when it is live; Context — start the agent when the runtime does report a window but the agent is not running; and Context — managed by the runtime for Claude and Codex agents, whose CLI owns its own context window — UnodeAi cannot measure it and has nothing of its own to compact. UnodeAi: Compact Context performs the same action from the Command Palette, so it can be bound to a key.

The per-turn context receipt is not the size of the request. It reads Attached context: N sources · ~X text tokens (estimate, attached sources only) and counts the attached sources alone; the conversation history, system prompt, and tool definitions consume the window without appearing there. A receipt of a few thousand tokens beside a gateway refusing the turn as too large is not a contradiction — the two measure different things, and the composer meter is the number compaction is decided from.

An agent learns its own ceiling from a refusal. A gateway rejecting a turn as too large is proof the model accepts less than was sent, so UnodeAi records that size as the model’s ceiling and compacts on its own before reaching it — the same conversation stops failing in the same place. The rejected request is not retried: it would fail identically and be billed again. Nothing is recorded when you set Context window yourself, when the limit is no tighter than one already known, or when the conversation is too small to explain the rejection (the system prompt, tool definitions, or attached project knowledge are carrying the weight, and compacting history cannot shrink them). A recorded ceiling is bound to the exact model that produced it, only ever tightens, and is saved with the agent roster so it survives a reload — travelling in .unode/team.json whenever the team file is written.

Team status is readable without colour. Collapsed roster rows carry a compact 18px status marker and a Status key. Done (✓), Verified (V), Tool activity recorded (…), Replied but not verified (↩), Consent required (🔒), and Denied — timed out (⌛) have distinct non-colour marks; long expanded details scroll within their own row and stale expanded ids are removed when an agent leaves the roster.

Composer and drafts. Two rows: the message box gets a full-width row of its own, and one control row beneath it carries the two auto-approve selectors on the left with Insert, Send and Stop on the right. Those three are icons rather than words — ↑ sends, ⚡ steers a running agent, ↓ queues a follow-up behind one, ■ stops — with the word on hover and in the accessible name, so nothing is lost to a screen reader. Below roughly 450px the Commands and Writes labels drop away while the selectors keep showing their current values: an approval setting must never hide what it is set to. The transcript keeps trailing scroll room sized to the input card, so the newest line always clears it, while scrolling back through history still slides the conversation beneath the translucent card; a short viewport returns the composer to normal flow. Unsent text belongs to its agent, not the panel: UnodeAi keeps up to 20 recent per-agent drafts and drops one when you send it or remove that agent.

Tool cards collapse to their title row, so a turn with twenty tool calls no longer buries the reply. Click a card's title row — or the ▶ on its right — to reveal that call's input, output, and diff. A blocked call opens by itself, because its error is the reason you'd look.

A refusal can name the safe next step without widening permission. Its bounded refusal reason may carry a reviewed host-authored explanation, but no path, credential, command, destination, or your free-form reason for denying a web request reaches the model. On OpenAI-compatible connections, task-only artifact and context-gap tools appear only during a live contracted attempt; a stale direct call still reaches the host handler for its accurate refusal. Claude's connection-time tool schema is unchanged.

Streaming text now keeps pace without rebuilding its open paragraph. Bursty text is revealed steadily, and a growing plain-text paragraph keeps its DOM node across paced paints so a selection inside it is not recreated by the next frame. Three authority boundaries that do not change the product surface now have their missing tests; the release runner requires all 12 targeted mutations to be killed.

Every finished step says how long it took. A completed tool card reads Done · 1.4s, and expanding it gives the absolute start, the absolute finish and the duration. A failed or blocked step is labelled the same way — how long something ran before it failed is often the more useful number. A coalesced group (for example “Read 4 files”) shows its span from first start to last finish. A duration is measured or it is absent; it is never shown as 0s. The finish time is recorded at the moment the call becomes a result, never inferred from when the card was drawn, so a card saved by a version before 0.9.63 says duration not recorded and a group containing one such step reports a partial span. There is deliberately no timeline, waterfall, statistics panel or timing export, and per-step timings do not appear in portable evidence.

The whole transcript renders, and a card you scroll away from and back to is the same card — it keeps its expanded state and its already-rendered content instead of being rebuilt. 0.9.63 briefly virtualised this and it was wrong: scrolling scheduled a redraw, the redraw replaced the transcript and pinned to the bottom, and pinning scrolled again, so both the Workbench and the Chat sidebar repainted at frame rate while a reply streamed. It was removed in 0.9.64, and a test now drives the real scroll listener in both containers and fails if a redraw is ever scheduled from one. Consent prompts, approvals, cancellations, evidence facts, errors and final answers are never omitted, reordered or merged by rendering; the sequence is tested against the real batching and animation-frame pacing before it ships.

A turn reports how long it took. Start, end and total elapsed, including time the request spent queued and time the agent spent thinking — a turn whose tool cards all read 0.1s can still have taken minutes, and before 0.9.68 nothing added that up. Time spent waiting for your approval is reported separately and is not in the total, because that was your time. A turn from before 0.9.68 says duration not recorded rather than showing a zero, and per-tool timings are unchanged.

0.9.68 removed every automatic prompt that pushed an agent to behave — five kinds, including two that scanned the agent's own sentences for phrases and injected a message when one matched. They cost a round-trip each and prevented nothing you could not already see. Verification did not get weaker: a task can declare what would prove it done, with real checks the extension runs and records, and the removed prompt was the version of that which asked nicely. Delegation also takes less paperwork — three contract fields that were required and usually empty are now optional, while the write scope stays required because it is what stops a delegated task writing outside the folders it was given. Nothing that protects you was removed: every safety property from earlier releases is re-tested each release by deliberately breaking it and confirming a test catches it.

0.9.70 keeps meaning with agents and facts with the host. Skill descriptions can be written in any language; the host checks their structural bounds rather than looking for English keywords. Conditional workflows branch only when the completing agent selects one exact label declared by the workflow, never because its prose contains a matching phrase. Workflows saved before 0.9.70 still load: an old substring condition becomes that exact label, and a branch that had no condition at all is kept as a fallback taken only when nothing else matched, which is never offered to the agent as a choice. A worker reports only which declared input is blocked; missing, expired, outside-task-scope, and unreadable come from the host's latest observation for that exact attempt. Coordinators can inspect their own durable task lifecycle after a result has been delivered without consuming it or waking the worker. Team Rules now separates display-only built-in protections, human-selected host policy, and advisory guidance. The extension also stopped reading a teammate's reply to decide whether it had claimed its checks passed: that scan was English-only and could mark a plain denial as a false claim, and what remains is the observed fact of whether a check ran. In a workspace you have not trusted, writes, edits, deletes and commands are refused at a single boundary that names Workspace Trust as the fix, with no per-command exception. Its first policy is off by default and applies only to structurally marked artifact reviews: require a different reported model identity, without claiming that this proves a different underlying model or a good review.

Task-scoped delegation keeps three things separate. A delegated task can carry a folder scope. What a relative path means is always the agent's configured working folder, resolved once, for reads and writes alike — a task scope never moves it. What may be touched is the scope's narrowed read and write roots, checked against the already-resolved file, and never wider than the agent's configured Folder Access. Where a command runs stays inside the writable part of the scope, because a shell is not a full filesystem sandbox and its starting directory is a real boundary. Before 0.9.65 the first two were one value, so a task scoped to research looked for research/x-article.md at research/research/x-article.md and reported a context gap; under a readwrite scope the doubled path was inside the scope, so the write was permitted and created the folder.

When an agent shows you a file, the extension publishes it. A tool card is a receipt, not the answer: the agent receives the whole file while the card shows a bounded preview. An agent now names the receipt the extension gave it and picks a state — shown publishes the whole file as the reply, partial publishes a prefix the extension cuts itself by character count, not-delivered publishes the stated reason and no content. It may add framing text before the content, but it never retypes the file, so nothing can be mistranscribed and nothing has to be checked. Showing you a document is one read and one publish. 0.9.66 got this wrong and 0.9.67 fixed it: for one release the agent had to reproduce the file character-for-character so the extension could compare the copy against the original it already held, a single trailing newline was enough to reject it, and it could not start over — one such request cost about four minutes on the strongest model available. Two rules are still enforced, because they prevent what you could not otherwise catch: content from an earlier turn cannot be published in a later one, and a turn has one final answer.

An input receipt records the file the extension opened, resolved on disk, so an absolute path, a relative one and a symlink to the same file all count as one read and letter case follows your filesystem rather than an assumption. That resolved path stays inside the extension — never on an input grant, never in the task card a teammate's model receives, and never exported. Portable evidence carries no filesystem paths and this is not the exception. Before 0.9.65 a receipt was matched against the text the model typed, so a file that had plainly been read could be recorded as unread.

A stuck run carries its next step. When a teammate returns nothing after the existing retry and fallback-model path, the card offers Edit agent model and then Retry delegation — and that retry is a genuinely new attempt with fresh input grants and the same permission, scope and file-claim checks as the first dispatch, never a revival of the delegation that ended. When an approval times out, the card states that the request cannot be resumed and offers nothing, because the tool call that asked for it already received its denial: an approval that expired can never become an approval, and its id is never re-used. Ask the agent again and it raises a fresh approval with a fresh window. Every repair is re-checked at the moment it is clicked — if the agent, the session or the remedy changed after the card was drawn, nothing runs and the card says why — and two clicks produce one retry. The panel sends an opaque host-issued id and a bounded action, never a target or a command.

Chat messages cross one declared boundary. Every command the chat view sends the extension has a single declared shape with bounded identifier lengths, validated once before any handler runs. This grants nothing: the view still names only opaque host-issued ids, and the extension re-derives every path and permission from its own state.

Activity clock. While a selected agent is running, the transcript keeps a tail line with the framework's real phase and elapsed time, such as Thinking – 8s or Running npm test – 14s. A running tool card shows the same elapsed time. The clock is local to the surface and disappears when the turn ends.

Readable progress. A real update_todos report appears as a collapsed summary such as 4 of 7 done · Wire the command; there is no placeholder when an agent reported no plan. Tool cards use distinct read, write, edit, search, run, delegation, and verification icons, and adjacent successful edits or commands collapse into a short outcome summary.

A file tool card is a bounded receipt, not the document. A read_file title says whether it holds Markdown or other file content. Markdown previews use the same structured renderer as replies; truncation states how much was omitted beside Open full file in editor. That action carries only the receipt's host-issued ids, and the extension resolves the recorded path and re-checks the agent's physical read roots before VS Code opens it. An expanded card remains expanded when later tool activity rebuilds its group, on transcript refresh, and after a Workbench reload.

Reading a document from your workspace

Since 0.9.69, read_file reads a PDF, Word document or PowerPoint deck from the folders an agent can already reach, and returns the text in the same tool result as any other file — same line window, same continue from here footer, no second tool call. This closed a real gap: UnodeAi could already read a PDF fetched from a public URL and one you attached to a chat message, and the file it could not open was the one already sitting in the folder you had opened.

Only the document's text is read. Embedded images, macros and any link the document points at are never opened, and nothing is fetched because a document asked for it. Parsing runs in a separate worker with its own memory limit and a timeout, so a corrupt or hostile file fails closed rather than affecting the editor. Permission is unchanged — a document outside an agent's read roots is refused exactly as any other file is. A scanned page reports that it needs OCR rather than returning empty text; UnodeAi performs no OCR. A plain .zip is still refused.

The activity feed

The Activity panel names the tool and what it acted on — a workspace-relative path for a file, a command's program name for a command — and repeated identical actions collapse into one line with a count, with a heartbeat updating that line rather than adding another. Before 0.9.69 an agent reading two different documents produced Using mcp__unode_files__read_file twice, because the entry carried the tool's internal name and not the file: two pieces of work looked like one repeated line. Nothing an external MCP tool passes as an argument is written into this feed, which persists and can be exported.

@roam in the VS Code Chat panel

UnodeAi also appears in the native VS Code Chat panel as @roam — alongside its own sidebar, both at once. Type @roam <goal> and your crew's PM picks it up, delegates, and streams the run back into the chat, with an Open in UnodeAi button for the full team view. It runs on your UnodeAi agents/models (not the chat panel's model), so you keep the multi-agent orchestration and cheap-model cost arbitrage. Needs at least one team; toggle with unode.chatParticipant.enabled.

PM Orchestration

One coordinator dispatches. The first Project Manager in a saved team is the single coordinator. Only it can dispatch, collect, or inspect task handles. A worker can send it a normal message proposing work, but the host never parses that prose; the coordinator decides whether to take a structured dispatch action. This temporarily removes worker fan-out until a hierarchy can keep every child handle visible to its lead.

Coordinator briefs get their own consent. A coordinator may attach short, sourced orientation to one delegated assignment. The worker sees it as a coordinator claim, not host evidence, and its cited inputs must be both declared and granted to that attempt or the dispatch is refused before work starts. Because a brief can paraphrase your documents and travels in the worker’s prompt rather than through a read tool, UnodeAi asks per dispatch when the worker’s resolved model destination differs from the coordinator’s, naming that destination in a modal. Declining refuses the dispatch; the same destination asks nothing new.

Shared memory keeps provenance without judging it. A memory_note is append-only and records the host-selected routing tier (premium, standard, or economy) plus the agent-selected kind (pitfall, contract, or decision). Tier is never accepted from a model argument and is not an underlying-model claim. Legacy notes render as unknown; prompt injection remains capped at 30 notes, with contracts retained before recency-selected other notes.

Send complex goals to the Project Manager. The PM breaks the work into a live todo list, asks the Architect for contracts when needed, delegates to teammates, collects results, runs checks, and sends work to an independent Reviewer.

Goal: Add password reset.
Scope: API route, email token model, UI form, tests.
Constraints: Keep the existing auth provider.
Verification: npm test and npm run build.

Best results come from clear scope, explicit constraints, and a configured unode.verifyCommand.

For independent work, the PM uses dispatch_task, shows Delegating · N out, and stays ready for your next instruction. When work lands while the PM is idle, one normal PM turn wakes with the evidence so it can report or continue on its own. If the PM is busy, the composer says how many delegated results are waiting behind that turn; the model does not wait or poll. collect_ready_tasks is optional and returns only results already settled. A result already settled but not yet delivered also remains available after a session resume; this does not claim that a still-running worker resumed. inspect_task_status keeps worker, wait-window, result, and read-receipt state separate; only a ready result names collect_ready_tasks.

An unfinished directed turn settles as partial. Its full report remains visible and its unfinished structured activity is carried separately. Partial stops the waiting card and wakes the coordinator, but it is never counted as a completed delivery or a green verdict. A workflow retains the report and pauses before its gate or next step.

New in 0.9.61: delegation is a host-checked task contract. The coordinator declares the deliverable, separate read and write effects, required capabilities, inputs, constraints, dependencies, verification sensors, and whether the work is delegate-preferred, delegate-required, or coordinator-only. The host filters permissions, task scope, file claims, input grants, artifact readiness, and sensor reachability before it chooses an executor. An unfit exact id is refused, role routing rotates only among survivors, the coordinator receives no looser path, and Solo is never an automatic fallback.

A refusal no longer has to be a dead end. The configured-workspace boundary has not relaxed: no newly readable or writable path is introduced, and a real path escape is still blocked and ends the turn. A shell line that merely looks out of root is still blocked and never executes, but it is a command-text heuristic rather than a filesystem proof, so the agent can make a different safe call. An expired, unsupported, or unforwarded temporary asset is likewise still unavailable and refused without ending useful work.

Inputs belong to one execution attempt. A contract can name a turn-supplied content asset, a current or dispatch-snapshot workspace path, or an explicit upstream artifact. The worker receives a task card rather than the coordinator’s conversation. Ending the attempt revokes its grants synchronously, including across retries, and an input never grants write, shell, web, or MCP authority. Only an immutable artifact-ready record can become a downstream dependency, and it retains the complete input provenance chain.

Missing context is a task state. report_context_gap uses missing, expired, outside-task-scope, or unreadable. The coordinator sees the declared purpose so it can supply, re-scope, or escalate; the worker and portable export do not learn whether an unauthorised source exists. Internal evidence keeps the compiled contract and supplied/reachable/read receipts—never “understood”. Portable evidence uses document-local input ordinals and omits the contract prose, paths, source ids, attempt ids, artifact handles, and provenance identities.

The input-substitution rule follows the contract. A card for a task declaring at least one required input tells the worker to report a context gap rather than substitute web content for material the host could not supply. A task declaring none — including one declaring only optional inputs — is told that no input-substitution rule applies, because optional means the work can be completed without that input. If a source must be consulted, declare it required. The card neither grants nor removes web access; that stays the agent’s configured capability.

Stopping work

While anything is running the status bar shows ⏹ Stop N. One click ends every running turn. It appears only while agents are working, so its presence is also the answer to "is the crew still going". The same action stays in the Team panel's ⋯ menu as UnodeAi: Stop All Agents. It ends turns — it is not a message asking agents to stop.

A coordinator can stop its own team. broadcast and send_message only deliver a message, and a teammate already mid-turn finishes regardless — so asking a PM to "stop everything" used to get a broadcast, an assurance, and no stop. cancel_task ends a teammate's turn: one assignment by handle, one teammate by name, or the whole team. Two limits are built in — a coordinator cannot stop itself, because that would end the turn making the call, and a solo agent belongs to no team, so stopping one is your button rather than a coordinator's.

Delegation evidence

Required-input receipts are host facts. A settled task records how many required inputs it declared and how many read receipts the host did not observe. A missing receipt is not proof that the worker did not read; actual access failures retain their separate missing, expired, outside-task-scope, or unreadable reason. Timeout and late-terminal snapshots remain separate. This does not reject the work automatically or replace the coordinator’s later decision.

A teammate's Done is not the verdict. Each delegation shows a framework-derived evidence state in the Workbench transcript, Activity, and the Team card: Verified, Tool activity recorded; delivery not checked, Replied, not verified, No evidence, Required input read receipt not observed, or Timed out. Completion is a separate fact, so a verified partial result remains both verified and partial. Changed files come from recorded checkpoints; passing checks come from the actual verifier record. Only a recorded write with a passing check is Verified. Informational work with tool activity is recorded without pretending that the framework judged its prose delivered.

Coordinator decisions are captured, not invented. After actually deciding whether to rely on a settled result, the PM may record accepted, rejected, or needs-human. This is optional: a result arriving alone is not a decision. Rejection and human-handoff records require a reason; a rejection forwards that reason to the delegate. If a prior framework verdict is rejected, the Workbench transcript, Activity, and the Team card show a visible amendment and its reason rather than silently rewriting the earlier line. The framework never uses an LLM or prose sentiment to infer this decision.

The session counter reports completed delegations, explicit coordinator acceptances, green framework verdicts later rejected, and explicit human-intervention requests. Coordinator-accepted is not enterprise or customer acceptance. The coordinator is an agent, and this counter measures agent decisions. A separate human verdict was added in 0.9.59 — see below — and the two are never merged.

Reviewing delivered work

A run nobody judged reports unjudged, never accepted. UnodeAi: Review Delivered Work shows a finished run’s evidence and asks a person for one verdict: accept, accept with exceptions (at least one open item required), or reject — a rejection being a real measured outcome, not a failure of the tool. Nothing converts a coordinator’s disposition, a green verified outcome, a closed run, or your silence into a human answer.

A run with delegated work still active cannot be judged and stays unjudged until it settles. Verdicts are append-only, so a later verdict is what the run reports while the earlier one stays readable, and runs from before 0.9.59 load as unjudged. A verdict needs a contemporaneous approver — the same rule already applied to command and write approvals. In portable evidence the verdict travels with a count of unresolved items and a document-local approver ordinal; the text you typed and the approver identity do not leave.

Keeping role guidance current

Agents that still use a role default receive updated guidance when they next start. Customized instructions are never overwritten. When a role default moves on, Agent Builder shows the diff between the default at customization time and the new default, so you can keep your version, reset to the new template with Undo, or merge the changes yourself.

Costs and Claude CLI Usage

The Team panel and Dashboard show token use and cost when a backend reports usage. Plain $... means billed spend. Claude Code subscription usage is API-equivalent and labelled ~$...; it is not a per-token invoice. If a completed turn has no observed cost basis, UnodeAi says cost unknown instead of displaying a fabricated $0. If ANTHROPIC_API_KEY is present in the Claude process environment, UnodeAi treats Claude usage as billed and shows plain dollars.

Model pickers label each known token price with its provider and provenance: for example $1.7/$5.1 per 1M · Roam (live). live means the configured gateway's pricing API supplied the value; list means the extension is using its built-in fallback. Prices are display-only and never borrowed from another provider.

What your key actually pays

A gateway publishes what a model costs. What your key is charged is settled inside the gateway and often not reported at all, so a published price can be several times what you pay — or, worse, look right while being wrong.

Two settings cover it, and both belong to the key rather than the account, because two keys on one account can sit in different billing groups with different prices and different callable models:

  • unode.priceGroup — names the billing group, per connection: { "unode": "vip", "roam": "default" }. Where a gateway offers several groups and you have not named one, UnodeAi shows the undiscounted rate rather than guessing the cheapest. An over-estimate is visible and your first invoice corrects it; an under-estimate takes money without warning.
  • unode.priceMultiplier — what fraction of the published price the key pays: 1 is list price, 0.33 a third of list, 0 free. UnodeAi asks for this when you store a key, because that is the one moment you are holding the fact.

Exactly one discount is applied. A stated coefficient and a gateway-reported group ratio answer the same question, so applying both would answer it twice. When you set a coefficient it is the one that counts — which means a stated 1 deliberately suppresses a discount the gateway would otherwise have applied. Leave a connection unset and the gateway answers. Every refresh states which of the two produced the number, in the Output channel.

An empty box is refused rather than read as free: "I do not know" and "it is free" are opposite ends of the range, and 0 already says the second one.

Prompt caching — the cached number

The Dashboard's Tokens card reads in / out / cached (N%). Cached input is prompt your provider served from its own cache, billed at roughly one tenth the price — on a long conversation it is most of what determines your bill.

Caching works on a prefix: everything before the first byte that changes can be reused, and everything from that byte on is re-read at full price. UnodeAi therefore keeps the stable part of a request — model, tool definitions, system prompt — byte-identical for the life of a session, and attaches volatile state (project rules, shared-memory notes, your open file) at the end of the request, where changing it cannot invalidate anything before it.

Dashboard status colours follow the active VS Code theme. Working and done use different semantic theme tokens. Where a testing-status token is unavailable, the earlier colour remains as a fallback so an indicator cannot become colourless.

Two things are worth knowing:

  • Claude caches nothing unless it is asked to. Every other provider caches automatically; Anthropic requires explicit cache markers in the request. UnodeAi sends them, and then checks whether they landed — because a missing cache does not fail, it only bills. If a route turns out not to cache, the agent's Output channel says so plainly instead of letting you find out on an invoice.
  • cached: not reported is not cached: 0. Some gateways don't pass the cache counter back. UnodeAi says "not reported" rather than showing a healthy-looking zero, and where it can reconstruct the real figure it labels it an estimate.

To see what one agent's caching is actually doing, open View → Output and pick UnodeAi · <agent>. It stays quiet while caching works, and speaks up when it doesn't.

Named custom gateways

New in 0.9.31. Add as many local OpenAI-compatible gateways as you like from Providers → Add custom gateway — each with its own display name, HTTPS endpoint, and API key. A gateway's identity is an opaque, immutable connection ID, not its name or its URL: rename it freely and every agent, Smart Mode mapping, and default stays bound to the same gateway. The key value never enters the Settings page; a card only reports whether a key is set.

Each gateway card carries the same flat action row as the built-in cards — Test connection · Edit · Set as default · Load models · Remove.

  • Edit walks name → endpoint → key (keep / replace / clear), then confirms with the old and new values and any agents affected. Endpoint and key changes are blocked only while an agent on that gateway is running; an idle agent does not block them. An agent started before the change is refused on its next request until you restart it, so no request goes to the endpoint you just replaced.
  • Remove is refused while an agent, the default, or a Smart Mode tier still points at the gateway, and it names exactly what to rebind. A removed ID is a tombstone and is never reused: a stale route becomes a visible repair rather than being silently redirected to some other gateway.
  • Test connection and Load models are the only network actions, both user-initiated. They ask for metadata consent for that host and touch only its own /models endpoint.

A workspace file cannot redefine any of this. An agent route stores only the connection ID and a model ID; the endpoint and the SecretStorage identity are derived in the extension host, so a hand-edited team file cannot point a stored key at another host. Prices and balances are never borrowed from a built-in gateway — an unknown custom price stays blank rather than showing a number from somewhere else.

Test connection now works on the built-in gateways too — Roam, Unode, OpenRouter, and OpenAI API, not just custom ones. Claude and Codex Headless have none, since they authenticate through their own CLI rather than a stored key.

Upgrading from the old single "Custom" connection? There is no button to press. If a trusted workspace still holds pre-0.9.31 custom agents, UnodeAi shows a preview of what it would create the next time it activates there, and changes nothing until you confirm. Two agents on two endpoints become two separate gateways; keys are copied only inside the extension host; migration makes no network request at all. Decline and nothing is written — those agents remain visible repairs, the prompt does not return for the same roster, and your team file keeps saving normally.

Execution hooks

unode.executionHooks is an inert candidate in every settings scope, including a repository’s .vscode/settings.json. To activate one, run UnodeAi: Apply Execution Hooks, inspect the complete normalized declaration, and confirm it. UnodeAi stores that approval outside the repository and binds it to both the declaration digest and its settings origin, so an edit or origin change makes the hook inert again. A hook can only block an action already available to an agent; it cannot grant file, shell, network, MCP, or model authority, and agents cannot edit the setting or approval record.

Late blocking results now resume the plan

If a teammate finishes after a blocking PM wait expires, the timeout is presented as unresolved rather than completed. The PM retains that result for a bounded two further wait windows and receives one normal wake with its existing evidence verdict when it arrives. Cancelling the run removes the listener, so stopped work cannot wake a PM later.

Choosing a model

The model field is a combobox, not a fixed list. Any id you type is sent to the provider exactly as written, whether or not the picker has heard of it — the suggestions are a convenience, never a limit.

Claude Headless leads with the CLI's always-latest aliases — opus, sonnet, haiku, fable — which the CLI resolves to the newest model in that family each time an agent starts. Pick an alias to stay current without ever editing settings; pick a pinned id such as claude-opus-5 when a run has to be reproducible later. Aliases are priced at their family's rate, so cost estimates still work.

This matters because a CLI cannot be asked what it serves: there is no claude models command, and an unknown --model prints a warning and still exits 0 — so an id can be neither discovered nor verified. A list frozen into the build was wrong again every release it was not hand-edited, which is why claude-opus-5 was once missing from the picker while typing it by hand worked fine.

Suggestions come from up to four layers, best first: unode.extraModels (yours, no reload), unode.modelCatalogUrl (a hosted catalog, reload required), the gateway's live /v1/models (OpenAI-compatible routes only, subject to metadata consent), then the built-in defaults.

Security

  • Provider keys are stored in VS Code SecretStorage.
  • A connection owns its endpoint and its key. An agent route stores only an opaque connection ID and a model ID; the extension host resolves the endpoint and the SecretStorage identity from its own registry. A hand-edited team file or a webview message cannot redirect a named gateway to another host or make it use another gateway's key, and an unknown or removed profile stays a visible repair instead of falling back to any default gateway.
  • File access is sandboxed to the workspace or assigned worktree, and individual agents can be narrowed to explicit Read / Read+Write folder grants in Agent Builder.
  • Command execution is controlled by unode.commandApproval.
  • Prompted-command frequencies stay local. unode.debug.promptedCommandLog is off by default and user-only. When you enable it for a review period, it records only the narrow CommandPolicy template for an approval prompt that was actually shown; it never retains raw arguments, URLs, or secrets, and has no network path.
  • On Windows, run_command uses cmd.exe: PowerShell cmdlets such as Copy-Item cannot be allowlisted for that shell. Use a cmd.exe equivalent or an agent shell that supports PowerShell.
  • Claude Headless uses a fail-closed pre-tool gate: shell commands keep the command approval, native writes honor write approval, and external or newly introduced Claude tools ask before running — even inside native subagents.
  • Codex Headless is not active in this release. The Coming soon route cannot launch a local Codex process; its future runner has separate security acceptance gates.
  • File writes can require diff approval with unode.writeApproval = ask.
  • MCP servers are default-deny and can require approval before mounting; the Security panel reviews each agent's MCP grants beside its folder grants.
  • Plan mode removes high-impact tools for OpenAI-compatible agents.
  • Zero data retention & no telemetry. UnodeAi itself keeps no copy of your code or prompts and has no analytics, tracking, or phone-home. Chat history, config, and keys stay on your machine; your code is sent only to the model provider you configure. UnodeAi works with any OpenAI-compatible endpoint, so you can point it at a self-hosted / in-VPC model for provable, end-to-end zero-retention.
  • Nothing beacons on install. No metadata path — price server, catalog, balance — contacts a host at activation until you approve one; the consent gate refuses an unapproved host before a packet moves. (Source-enforced and tested; the absolute "zero traffic of any kind" is marked UNVERIFIED in SECURITY.md pending a clean-profile packet capture.)
  • Two separate network grants, both revocable. Sending a host your prompts and code (model egress) is one grant; fetching its price list, model list, and your account balance (metadata — never any code) is another, asked with an accurate description only when you open a model picker or refresh prices. Opening one provider's picker never contacts another provider's gateway. The Security panel lists each grant on its own row with its own revoke.
  • Public-web requests are separately controlled. Gateway fetch_url and Claude WebSearch/WebFetch require an agent's read capability and follow unode.webAccess, which defaults to ask. The approval card can allow one request, deny it, or allow the whole crew for this extension session; the session choice is not persisted. With off, or without read access, those tools are not advertised and the host still denies a stale direct request. A denial is shown as refused on the tool card from the host's structured decision, never guessed from English result text; MCP and subprocess output remains explicitly external.
  • Claude startup consent is actionable. When a native model-egress dialog is open, the agent shows Consent required rather than remaining on Starting. Answer the already-open dialog: Allow resumes the same start, Cancel reports an error, and stopping first prevents a later Allow from spawning the process.
  • The hosted skill catalog is verified or it is nothing. A remote catalog merges only with a valid publisher signature over its exact bytes; unsigned or tampered content is rejected and the bundled catalog stands.

Use unode.commandApproval = all only inside a sandbox or disposable environment.

Verified worktree fan-out

For larger parallel jobs, set unode.concurrencyStrategy = worktree (requires a git repo with a clean tree). Each eligible agent gets its own isolated git worktree under .unode/worktrees/; when its turn finishes, its work is committed and merged into a Roam integration branch (unode/integration).

Only work that passes your checks lands. Before merging, UnodeAi runs your unode.verifyCommand (build/lint/test) inside that agent's worktree. If it passes, the work merges; if it fails, the work is held on the agent's own branch and handed back to fix — nothing unverified reaches integration. Neither Cline nor Kilo gate the team merge on verification.

A successful Git command is not automatically a merge. UnodeAi compares the integration branch's HEAD before and after the command. If it did not move, the lane says nothing to merge; if it moved, the lane says merged, independent of Git's display language.

  • Review with UnodeAi: Crew Worktrees (Review) — each lane shows ✓ verified / ✗ failing / ⚠ unverified, and a lane that passed by editing the tests (instead of fixing the code) is flagged for review.
  • Land integration work onto your branch with UnodeAi: Finalize Worktree Merges to Branch.
  • Gate is controlled by unode.worktree.verifyBeforeMerge (on by default) + unode.worktree.verifyTimeoutSeconds; with no unode.verifyCommand there's nothing to gate on and merges proceed.
  • Control parallelism with unode.worktree.maxParallel; leave unode.worktree.autoMerge off when you want manual review.
